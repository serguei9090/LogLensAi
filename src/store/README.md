# State Stores (`src/store`)

## Overview
Zustand state management layer for LogLensAi covering AI chat/SSE streaming, Drain3 clustering state, diagnostic logging, sidecar health monitoring, per-source investigation snapshots, Laya decision-engine rules/models, application settings, persisted UI layout preferences, and workspace/hierarchy management. Modular ingestion job polling and import form state reside in `./ingestion`.

## Interface
- `useAiStore`, `SessionType`, `AiMessage`, `AiSession` (`[aiStore.ts:useAiStore]`, `[aiStore.ts:SessionType]`, `[aiStore.ts:AiMessage]`, `[aiStore.ts:AiSession]`): Manages isolated investigation and dashboard AI sessions, SSE chat streaming (`sendMessage`, `stopStream`), `[[A2UI]]`/`[[EVAL_NOTICE]]` extraction, and log-to-session mapping (`fetchMapping`).
- `useClusteringStore`, `ClusteringMode`, `ClusteringStatus` (`[clusteringStore.ts:useClusteringStore]`, `[clusteringStore.ts:ClusteringMode]`, `[clusteringStore.ts:ClusteringStatus]`): Holds Drain3 clustering status and exposes `fetchStatus`, `setMode`, and `setPaused`.
- `useDebugStore`, `DebugLog` (`[debugStore.ts:useDebugStore]`, `[debugStore.ts:DebugLog]`): In-memory reverse-chronological log buffer (`addLog`, `clearLogs`, `setOpen`).
- `useHealthStore`, `HealthStatus` (`[healthStore.ts:useHealthStore]`, `[healthStore.ts:HealthStatus]`): Tracks sidecar connectivity, hydration misses/quarantine size, and worker status (`fetchHealth`, `setPolling`).
- `useInvestigationStore`, `SourceState`, `InvestigationStore` (`[investigationStore.ts:useInvestigationStore]`, `[investigationStore.ts:SourceState]`, `[investigationStore.ts:InvestigationStore]`): Manages search query, filters, highlights, logs, sort order, time range, facets, selections, and `syncActiveSource` per-source state snapshots.
- `useLayaStore` (`[layaStore.ts:useLayaStore]`): Manages Laya settings, rule checkpoints (`fetchCheckpoints`, `rollbackCheckpoint`, `saveRules`), rule testing (`testRule`, `clearTestResult`), and ONNX model lifecycle (`fetchModelStatus`, `downloadModel`, `deleteModel`).
- `useSettingsStore`, `AppSettings`, `KeyboardShortcut`, `defaultSettings` (`[settingsStore.ts:useSettingsStore]`, `[settingsStore.ts:AppSettings]`, `[settingsStore.ts:KeyboardShortcut]`, `[settingsStore.ts:defaultSettings]`): Hydrates settings from the sidecar, caches verified providers and model lists, and batches setting updates (`updateSettings`, `flushPendingSettings`).
- `useUIStore`, `CustomColumnDef` (`[uiStore.ts:useUIStore]`, `[uiStore.ts:CustomColumnDef]`): Persists navigation view, sidebar collapse states, table column config/custom regex columns, and cluster diagnostic drawer state (`openDiagnostic`, `closeDiagnostic`).
- `useWorkspaceStore`, `LogSource`, `Folder`, `HierarchyNode`, `Workspace`, `selectActiveWorkspace`, `selectActiveSource` (`[workspaceStore.ts:useWorkspaceStore]`, `[workspaceStore.ts:LogSource]`, `[workspaceStore.ts:Folder]`, `[workspaceStore.ts:HierarchyNode]`, `[workspaceStore.ts:Workspace]`, `[workspaceStore.ts:selectActiveWorkspace]`, `[workspaceStore.ts:selectActiveSource]`): Persists workspaces and manages sources, folders, and hierarchical trees (`fetchHierarchy`, `createSource`, `removeSource`, `renameSource`, `createFolder`, `updateFolder`, `deleteFolder`, `moveSource`).
- Child package: [Ingestion Store](./ingestion/README.md) — `useIngestionStore`, `createImportSlice`, `createTrackingSlice`, `createPollingSlice`, `traceIngestion`, and ingestion store types.

## Invariants
- AI session domain isolation: `useAiStore` partitions sessions into `dashboardSessions` (name containing `"dashboard"`, `session_id` starting with `"dash-"`, or `session_type === "dashboard"`) and `sessions`, keeping `dashboardSessionId`/`dashboardMessages` independent from `currentSessionId`/`messages` (`[aiStore.ts:useAiStore]`).
- Bounded debug log ring buffer: `useDebugStore.addLog` prepends new entries and slices `logs` to `MAX_LOGS` (`500`) (`[debugStore.ts:useDebugStore]`).
- Health status classification: `useHealthStore.fetchHealth` marks health `"degraded"` if `!res.workers.clustering`, `!res.workers.ingestion`, or `res.hydration.misses > 100`, and `"unreachable"` on transport error (`[healthStore.ts:useHealthStore]`).
- Per-source investigation snapshot isolation: `useInvestigationStore.syncActiveSource` maps `null` to `"aggregate"`, no-ops when `nextId === currentSourceId`, and saves the current `SourceState` into `sourceStates` before restoring the next source's state (`[investigationStore.ts:useInvestigationStore]`).
- Coalesced settings persistence: `useSettingsStore.updateSettings` updates local state optimistically, accumulates deltas into `pendingSettingsPayload` (JSON-stringifying `drain_masks` and `facet_extractions`) over a 300 ms `saveTimeout`, and `flushPendingSettings` clears any timer to dispatch immediately; `fetchSettings` attempts Python-literal JSON normalization if standard `JSON.parse` fails (`[settingsStore.ts:useSettingsStore]`).
- Mutually exclusive sidebars & column placement: `useUIStore` collapses `columnManagerCollapsed` when opening `facetSidebarCollapsed` (and vice versa), and `addCustomColumn` inserts new columns before `"message"` in `columnOrder` (`[uiStore.ts:useUIStore]`).
- Workspace & source selection invariants: `useWorkspaceStore.addWorkspace` rejects duplicate IDs; `setActiveSource` clears `activeFolderId` and `setActiveFolder` clears `activeSourceId`; `fetchHierarchy` retains `activeSourceId` only if present in `flatSources` (`[workspaceStore.ts:useWorkspaceStore]`).
- Clustering polling delegation: `useClusteringStore` maintains no internal polling timer; `fetchStatus` is triggered externally by `useIngestionStore` (`[clusteringStore.ts:useClusteringStore]`).

## Side Effects
- Sidecar JSON-RPC calls via `callSidecar`: `useAiStore` (`get_ai_sessions`, `get_ai_mapping`, `rename_ai_session`, `delete_ai_session`, `get_ai_messages`), `useClusteringStore` (`get_clustering_status`, `set_clustering_mode`, `set_clustering_paused`), `useHealthStore` (`get_health`), `useLayaStore` (`get_laya_model_status`, `download_laya_model`, `delete_laya_model`, `get_laya_settings`, `update_laya_settings`, `get_laya_checkpoints`, `rollback_laya_checkpoint`, `save_laya_rules`, `test_laya_rule`), `useSettingsStore` (`get_settings`, `update_settings`), `useUIStore` (`analyze_cluster`), and `useWorkspaceStore` (`delete_workspace`, `create_log_source`, `delete_log_source`, `update_log_source`, `get_hierarchy`, `create_folder`, `update_folder`, `delete_folder`, `move_source`) (`[aiStore.ts:useAiStore]`, `[clusteringStore.ts:useClusteringStore]`, `[healthStore.ts:useHealthStore]`, `[layaStore.ts:useLayaStore]`, `[settingsStore.ts:useSettingsStore]`, `[uiStore.ts:useUIStore]`, `[workspaceStore.ts:useWorkspaceStore]`).
- HTTP streaming & timers: `useAiStore.sendMessage` streams SSE events from `${SIDECAR_BASE_URL}/api/stream_chat` via `fetch` + `AbortController` and schedules a 200 ms `setTimeout` message reload (`[aiStore.ts:useAiStore]`); `useLayaStore.downloadModel` polls `get_laya_model_status` via a 1,500 ms `setInterval` (`[layaStore.ts:useLayaStore]`); `useSettingsStore` schedules a 300 ms debounce `setTimeout` (`[settingsStore.ts:useSettingsStore]`).
- Browser `localStorage` persistence: `useSettingsStore` reads/writes `loglens_verified_providers` and `loglens_provider_models_cache` (`[settingsStore.ts:useSettingsStore]`); `useUIStore` persists partialized state under `"loglensai-ui-state"` (`[uiStore.ts:useUIStore]`); `useWorkspaceStore` persists state under `"loglensai-workspaces-v4"` (`[workspaceStore.ts:useWorkspaceStore]`).
- Global DOM events & toast notifications: `useWorkspaceStore` dispatches `CustomEvent("loglens:remove-source-jobs")` in `removeSource` and registers a `loglens:refresh-hierarchy` listener on `globalThis` (`[workspaceStore.ts:useWorkspaceStore]`); `useAiStore` emits `sonner` `toast.error` notifications on session/message errors (`[aiStore.ts:useAiStore]`).
